# منظومة متابعة نماذج الدورة المستندية للمشاريع

تطبيق متعدد المنصات (أندرويد، آيفون، ويندوز، الويب) لمكتب الشؤون الهندسية — لجنة إعادة إعمار منطقة الصابري ووسط البلاد.
مبني بـ **Flutter**، وبياناته في **Supabase** (قاعدة PostgreSQL) على حساب مدير المكتب.

مدير المكتب هو المسؤول الأول والأخير:
- لا يدخل أحد المنظومة إلا بعد أن يفعّل حسابه ويحدد دوره.
- النماذج الحساسة (المستخلصات، الاستلام، إقفال العقد) لا تتغير إلا بقراره.
- وحده يحذف المشاريع ويضبط صلاحيات النماذج ويرى سجل التدقيق كاملاً.

هذه القواعد مفروضة داخل قاعدة البيانات نفسها (Row Level Security)، فلا يمكن تجاوزها من أي نسخة من التطبيق.
التحليل الكامل (الفاعلون، مخطط حالات الاستخدام، مصفوفة الصلاحيات) في `docs/نموذج_حالات_الاستخدام.html`.

## محتويات المشروع

```
lib/                      شيفرة التطبيق
  main.dart               نقطة البداية واللغة العربية
  config.dart             عنوان Supabase ومفتاحه
  models.dart             النماذج وحساب نسبة الإنجاز
  app_state.dart          البيانات والتحديث اللحظي والعمليات
  screens/                الشاشات: الدخول، الرئيسية، المشاريع، المشروع، الاعتمادات، التحليل، الإدارة
  services/export.dart    التصدير إلى Excel
supabase/
  migrations/             ملفا قاعدة البيانات (يُشغَّلان بالترتيب)
  tests/                  اختبارات الصلاحيات ومسار الاعتماد (65 اختباراً)
tool/prepare_platforms.sh يُنشئ مجلدات المنصات ويضبط اسم التطبيق
.github/workflows/        البناء الآلي لكل المنصات
test/                     اختبارات حساب الإنجاز
```

## الإعداد لأول مرة

### 1. أنشئ مشروع Supabase باسمك
1. ادخل [supabase.com](https://supabase.com) بحسابك وأنشئ مشروعاً جديداً (اختر أقرب منطقة، مثل Frankfurt).
2. احتفظ بكلمة مرور قاعدة البيانات في مكان آمن.

### 2. أنشئ قاعدة البيانات
من لوحة المشروع: **SQL Editor** ← **New query**، ثم الصق وشغّل الملفين بالترتيب:
1. `supabase/migrations/20261026000001_schema.sql` — الجداول والصلاحيات ومسار الاعتماد.
2. `supabase/migrations/20261026000002_import_projects.sql` — المشاريع السبعة عشر من ملف Excel.
3. `supabase/migrations/20261026000003_admin_email.sql` — تغيير بريد الدخول من التطبيق.
4. `supabase/migrations/20261026000004_releases.sql` — الإصدارات والتحديث التلقائي.

### 3. اضبط تسجيل الدخول
من **Authentication** ← **Sign In / Providers** ← **Email**:
- أبقِ تسجيل الدخول بالبريد مفعّلاً.
- **Confirm email**: إن أبقيته مفعّلاً يصل لكل موظف بريد تأكيد قبل أول دخول. لمنظومة داخلية يمكن إيقافه، فالتفعيل الفعلي بيدك من شاشة الإدارة على أي حال.

### 4. انسخ بيانات الربط
من **Project Settings** ← **API**: انسخ **Project URL** والمفتاح العام (**anon** أو **publishable**).
لا تستخدم مفتاح **service_role** في التطبيق أبداً؛ هذا المفتاح لك وحدك.

### 5. أنشئ حسابك وامنح نفسك دور المدير
1. شغّل التطبيق (القسم التالي) وأنشئ حسابك من «حساب جديد».
2. في **SQL Editor** شغّل مرة واحدة، مع بريدك:
   ```sql
   select public.claim_director('بريدك@مثال.com');
   ```
   تعمل هذه الدالة مرة واحدة فقط، ولا تُستدعى من التطبيق.
3. سجّل الدخول من جديد؛ تظهر لك شاشة «الإدارة».

### 6. أضف فريقك
يُنشئ كل موظف حسابه من التطبيق، فيظهر لك في **الإدارة ← المستخدمون** «بانتظار التفعيل». اختر دوره (والقسم لرئيس القسم) وفعّله.

## البناء

### الطريقة الأسهل: البناء الآلي على GitHub
1. ارفع المجلد إلى مستودع خاص على GitHub.
2. أضف في **Settings ← Secrets and variables ← Actions** سرّين: `SUPABASE_URL` و `SUPABASE_ANON_KEY`.
3. افتح تبويب **Actions** وشغّل **build**.
4. بعد انتهائه تجد في صفحة التشغيل:
   - `android-apk` — ملف APK يُثبَّت مباشرة على أجهزة أندرويد.
   - `windows-setup` — برنامج تثبيت ويندوز (`dc-app-setup.exe`).
   - `web` — موقع جاهز للرفع على أي استضافة ثابتة.
   - `ios-unsigned` — نسخة آيفون غير موقّعة، من سير العمل المنفصل **ios** (أجهزة Mac على GitHub تكون مزدحمة أحياناً، فيمكن إعادة تشغيله مع اختيار نوع جهاز آخر). تحتاج حساب Apple Developer لتوقيعها وتوزيعها.

عند كل رفع يعمل أولاً الفحص السريع **check** (تحليل الشيفرة، الاختبارات، اختبار قاعدة البيانات، تجميع الويب)، وإن نجح على الفرع main يبدأ البناء الكامل تلقائياً. أي خطأ يظهر كتنبيه في صفحة التشغيل.

### على جهازك
1. ثبّت Flutter (الإصدار المستقر) من [docs.flutter.dev](https://docs.flutter.dev/get-started/install).
2. داخل مجلد المشروع:
   ```bash
   bash tool/prepare_platforms.sh
   flutter pub get
   flutter test
   ```
3. للتجربة على المتصفح:
   ```bash
   flutter run -d chrome --dart-define=SUPABASE_URL=https://xxxx.supabase.co --dart-define=SUPABASE_ANON_KEY=المفتاح
   ```
4. للبناء (أضف السطرين `--dart-define` نفسيهما لكل أمر):
   | المنصة | الأمر | يتطلب |
   |---|---|---|
   | أندرويد | `flutter build apk --release` | Android Studio |
   | ويندوز | `flutter build windows --release` | جهاز ويندوز مع Visual Studio (C++) |
   | الويب | `flutter build web --release` | — |
   | آيفون | `flutter build ipa --release` | جهاز Mac مع Xcode وحساب Apple Developer |

بدلاً من `--dart-define` يمكن كتابة العنوان والمفتاح في `lib/config.dart` مباشرة.

## التوزيع على الأجهزة

- **أندرويد:** أرسل ملف APK للموظفين وثبّتوه (مع السماح بالتثبيت من مصادر خارجية)، أو انشره على Google Play.
- **آيفون:** عبر TestFlight أو App Store، ويتطلب حساب Apple Developer.
- **ويندوز:** انسخ مجلد البرنامج كاملاً إلى الجهاز.
- **الويب:** ارفع محتوى `build/web` على أي استضافة (GitHub Pages أو Netlify أو خادم الصندوق)، ويعمل من أي متصفح على أي جهاز.

## إصدار تحديث للموظفين (التحديث التلقائي)

قرار الإصدار بيد مدير المكتب وحده:
1. جرّب التعديلات أولاً من نسخ البناء التجريبية (سير العمل **build**).
2. من تبويب **Actions** اختر **release** ← **Run workflow**، واكتب ما الجديد، وحدّد إن كان التحديث **إلزامياً**، ثم **Run workflow**.
3. خلال نحو 15 دقيقة تُبنى نسخ أندرويد وويندوز والويب برقم إصدار جديد، وتُرفع إلى Supabase، ويُنشر الويب على Netlify.
4. كل نسخة مثبّتة تكتشف الإصدار الجديد لحظياً، فيظهر للموظف شريط «يتوفر الإصدار …» مع زر التنزيل. الإصدار الإلزامي يوقف التطبيق القديم حتى يُحدَّث.

متطلبات لمرة واحدة:
- تشغيل `supabase/migrations/20261026000004_releases.sql` في Supabase.
- أسرار المستودع: `SUPABASE_SERVICE_KEY` (المفتاح السري sb_secret، لرفع ملفات الإصدار فقط)، و`ANDROID_SIGNING_PASSWORD` (كلمة سر مفتاح التوقيع)، واختيارياً `NETLIFY_AUTH_TOKEN` و`NETLIFY_SITE_ID` لنشر الويب.

مفتاح توقيع أندرويد محفوظ مشفّراً في `tool/signing/release.p12.enc`. **احتفظ بكلمة سرّه في مكان آمن**؛ بدونها لا يمكن تحديث التطبيق المثبّت على الهواتف، ويلزم حذفه وتثبيته من جديد.

يُحتفظ بآخر ثلاثة إصدارات لكل منصة في Supabase، وروابط ثابتة لأحدث نسخة:
`<SUPABASE_URL>/storage/v1/object/public/releases/android/latest.apk` و `.../windows/latest-setup.exe`.
لهواتف أندرويد القديمة بمعالج 32 بت: `.../android/latest-arm32.apk` (التطبيق يختار النسخة المناسبة تلقائياً عند التحديث).

### ويندوز: برنامج تثبيت وتحديث ذاتي
- يُثبَّت البرنامج مرة واحدة من `latest-setup.exe` للمستخدم الحالي دون صلاحيات مدير، في `%LOCALAPPDATA%\Programs\DocumentCycle`، مع اختصار في قائمة ابدأ وعلى سطح المكتب، ويظهر في «التطبيقات المثبّتة» لإزالته.
- عند صدور إصدار جديد يضغط الموظف «تحديث الآن»، فينزّل البرنامج برنامج التثبيت ويثبّته بصمت ثم يعيد تشغيل نفسه.
- برنامج التثبيت غير موقّع رقمياً، فقد يُظهر ويندوز تحذير SmartScreen عند أول تثبيت من المتصفح: **مزيد من المعلومات** ← **تشغيل على أي حال**. التحديثات من داخل البرنامج لا تُظهر هذا التحذير. لإزالته نهائياً يلزم شراء شهادة توقيع شيفرة.

## الهوية البصرية

ألوان التطبيق وأيقونته مأخوذة من شعار صندوق التنمية وإعادة إعمار ليبيا ولجنة إعادة إعمار منطقة الصابري ووسط البلاد: الشعار الكامل في شاشة الدخول، والختم الدائري في الشريط العلوي وأيقونة التطبيق، وشريط ألوان العلم تحت الشريط العلوي. ملفات الشعار في `assets/brand/`، وتُولَّد الأيقونات لكل المنصات تلقائياً عند البناء.

## تغيير بريد الدخول

يغيّره مدير المكتب من **الإدارة ← المستخدمون** لأي موظف، ومن قائمة الحساب ← **تغيير بريد الدخول** لحسابه هو. التغيير فوري، وكلمة المرور تبقى كما هي، ويُسجَّل في سجل التدقيق. يتطلب تشغيل ملف `supabase/migrations/20261026000003_admin_email.sql` مرة واحدة.

## الأدوار

| الدور | ما يستطيعه |
|---|---|
| مدير المكتب | كل شيء، وتعديلاته تُنفَّذ مباشرة. وحده: الاعتماد، المستخدمون، صلاحيات النماذج، الحذف، سجل التدقيق الكامل |
| موظف مكتب المدير | إضافة المشاريع وتعديل بياناتها، وتحديث كل النماذج (الحساسة بطلب اعتماد) |
| رئيس القسم | نماذج اختصاص قسمه فقط (القسم المشرف: الإشراف والتنسيق أو الترميم؛ الشؤون الفنية: الحصر؛ المطابقة والاستلام: محاضر الاستلام) |
| مكتب العقود والتوريدات والمستخلصات | نماذج التعاقد والمستخلصات المالية وإقفال العقد |
| مكتب التخطيط والتقييم وضمان الجودة | اطلاع كامل وتصدير، وتسجيل ملاحظات التقييم والجودة |

توزيع النماذج على الأدوار وتحديد النماذج الحساسة قابلان للتعديل من **الإدارة ← صلاحيات النماذج** دون أي برمجة.

## الأمان والنسخ الاحتياطي

- كل الصلاحيات مفروضة في قاعدة البيانات؛ التطبيق يعرض الأزرار فقط.
- سجل التدقيق لا يُعدَّل ولا يُحذف.
- لتغيير مدير المنظومة مستقبلاً (مثلاً عند التكليف بمدير جديد) يُعدَّل من لوحة Supabase مباشرة بحسابك، وليس من التطبيق.
- النسخ الاحتياطي: **Database ← Backups** في لوحة Supabase (يومي في الخطط المدفوعة)، أو صدّر السجل إلى Excel من شاشة التحليل بشكل دوري.

## اختبار قاعدة البيانات محلياً

مع PostgreSQL 16 يعمل على الجهاز:
```bash
bash supabase/tests/run_tests.sh localhost 5432
```
يُنشئ قاعدة اختبار مؤقتة ويشغّل 65 اختباراً للصلاحيات ومسار الاعتماد.

## حدود الإصدار الأول

- الإشعارات داخل التطبيق (أيقونة الجرس مع التحديث اللحظي)، دون إشعارات دفع على الهاتف وهو مغلق.
- لا يعمل التطبيق دون اتصال بالإنترنت.
- أيقونة التطبيق هي الأيقونة الافتراضية لـ Flutter.
